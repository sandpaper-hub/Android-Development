`IntrinsicSize` в Jetpack Compose — это вспомогательный объект, который используется вместе с `Modifier.width(...)`, `Modifier.height(...)` или `Modifier.size(...)` для того, чтобы контейнер сам вычислил свою размерность исходя из «внутренних» (intrinsic) размеров своих детей.

---

По умолчанию в Compose контейнер при измерении сначала сообщает детям, сколько места у него есть, а потом сам подгоняется под их реальный размер. Но иногда нужно поступить наоборот:

- Сначала выяснить, **какого минимального или максимального размера** требует каждый ребёнок (intrinsic размер),
    
- А уже потом установить контейнеру именно такой размер.
    

Это полезно, например, чтобы сделать две колонки одинаковой высоты по самому высокому элементу, либо заставить строку текстов выровняться по самому широкому.

---

## Основные константы

```kotlin
enum class IntrinsicSize {
  Min,  // минимальный необходимый размер, чтобы поместился содержимый контент
  Max   // максимальный из предсказанных размеров (для выравнивания соседних элементов)
}
```

---
### 1. Выравнивание высот

Представим две строки текста разной длины: одна короткая, вторая — многострочная. Чтобы их контейнеры (колонки) были одинаковой высоты:

```kotlin
Row(Modifier.height(IntrinsicSize.Min)) {
    Column(Modifier.weight(1f)) {
        Text("Короткий")
    }
    Column(Modifier.weight(1f)) {
        Text("Очень длинный текст, который займёт несколько строк и сделает колонку выше")
    }
}
```

Здесь `Row` сначала спрашивает у каждого `Column` его **min intrinsic height** (минимальную высоту, чтобы уместился весь текст), и затем сам выставляет себе именно эту высоту. В итоге обе колонки получат одинаковую высоту — ту, что требуется более высокому элементу.

### 2. Выравнивание ширин

Аналогично можно выровнять ширину соседних элементов:

```kotlin
Column(Modifier.width(IntrinsicSize.Min)) {
    Text("Короткий текст")
    Text("Очень длинный текст, который займёт больше места по ширине")
}
```

`Column` сначала узнаёт **min intrinsic width** каждого `Text`, берёт максимальное из них и сам становится именно такой ширины.

---

## Когда не стоит использовать

- Избегайте IntrinsicSize на **очень больших** или **ленивых** списках – предварительный проход за всеми элементами (для вычисления intrinsic размеров) может быть дорогим по производительности.
    
- Лучше применять на небольших статичных наборах или одиночных компонентах.
    

---

- **IntrinsicSize.Min** и **Max** позволяют контейнеру узнать, какого минимального (или максимального) размера требует его содержимое _до_ фактического измерения.
    
- Это помогает выравнивать по размеру «соседние» элементы там, где обычные `Modifier.fillMaxSize()`/`wrapContentSize()` не дают нужного эффекта.
